# 考研 + AI + 记忆曲线：用 14 天虚构重放跑通一个开源学习引擎

投稿草稿，尚未在知乎或掘金发布。本文验证的是软件流程，所有演示作答均为虚构数据，
没有真实考生提分、效率提升或个人记忆曲线验证结论。

## 从一次“看懂了”说起

看懂讲解、照着提示完成、独立做对和隔几天仍能重建，提供的证据并不相同。
如果学习档案只留下一句“掌握了”，后续很难知道该复习什么，也很难核对判断是否有依据。

Postgrad Study Engine 尝试把这个问题拆开：交互层负责教学，公共 Core 处理合格证据、状态重建
与模型计算，每位学习者的私人 Vault 保存各自的观察。考研是起点，通用引擎与私人数据分离。

项目：https://github.com/wysking/postgrad-study-engine

## 跑一个可以检查的演示

需要 Git 和 Python 3.12。从干净的发布检出运行：

```sh
git clone --branch v0.5.0 https://github.com/wysking/postgrad-study-engine.git
cd postgrad-study-engine
python -m scripts.study demo --vault ../fictional-study-demo
python -m scripts.study today --vault ../fictional-study-demo --as-of 2026-08-15T09:00:00Z
```

演示有九个知识单元、十四次作答和一次诊断，跨越十四个自然日间隔。
打开 `reports/demo.html` 可以看到：一次独立正确不会立即变成稳定掌握；第三天的失败、
辅助纠正、独立变式与后续检查分别保留。文件夹已存在时初始化会拒绝覆盖。

这些记录是为了检验实现而编写的控制数据，不是维护者或任何学生的真实学习经历。
真实使用应另建空白私人 Vault，不复制演示作答。

## 曲线拟合到底算什么

第一版基线使用 `R(t,H)=2^(-t/H)`。对有明确成功锚点、实际间隔、已知帮助条件和结果的
原子回忆样本，程序拟合有界、正则化的半衰期 H。零样本也能运行，但明确输出先验状态；
没有已知锚点时，当前保持率为空。综合数学求解不会被重新标记成记忆卡。

可选 FSRS 适配还要求实际观察到的难易评分。一次做对不能自动被程序解释为 Good 或 Easy。
模型版本、来源哈希、训练截止与样本使用/排除理由一起保存，输出可以删除后重建。

项目同时提供按时间预测后再更新的评估，以及固定种子的合成检查。后者先拟合二十四个
虚构学习者各自的前二十次结果，再固定参数评估后续四百八十次预测。
生成数据遵循模型自己的函数形式，因此它验证的是拟合流程在声明假设下的行为；
它不能证明真实人的遗忘过程、长期保持或不同调度策略的效果。

## 少刷题的合理目标是“先核查”，不是宣称已经找全

引擎可以依据已配置的先修关系、真实观察到的错误和证据缺口，提出待验证假设，建议少量
有区分力的探针。当前是透明的启发式排序，不声称已经实现经过验证的信息增益最优选题。

一道题只能提供局部证据。未覆盖内容、迁移和整卷能力仍需要实际检查；模型不能把生成的
题目或标准答案记成学习者作答。v0.5.0 的正式排程仍使用原规则和真实时间预算。

## 怎么接 ChatGPT，怎么保护档案

仓库有教学 Skill、离线参考入口和可选 OpenAI Responses 适配。交互层从当前问题出发，
给分级提示、观察真实步骤，再通过结构化请求保存紧凑证据。只有匹配回执和实际归档结果
核对通过，才能报告相应保存成功。

公共仓库只放通用代码与虚构示例。私人记录、参数和报告留在各自的 Vault。
Markdown 文件可用 Obsidian 等工具查看，但项目没有专用插件或自动双向同步。
它目前提供 CLI 和本地 HTML，不是带托管账号系统的刷题 App。

## 现阶段适合谁

如果你愿意从可复现演示入手，想让 AI 辅助学习的判断有可核对的证据，欢迎试用或贡献课程包、
边界测试与评估方法。若希望直接打开完整题库、获得跨学科已校准预测或提分承诺，当前版本
还不能提供这些结果。
